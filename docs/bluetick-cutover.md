# The bluetick cutover

How Sharwin Table Tennis Academy stops being a web app and becomes a WhatsApp
business with a website in front of it — and how to undo that if it goes wrong.

## What moved where

| Was | Is now |
| --- | --- |
| `/app` — client booking, membership, schedule, notifications | A WhatsApp thread with bluetick's assistant |
| `/coach` — today's sessions, attendance, notes | The same thread, from the coach's own number |
| `/admin` — calendar, classes, coaches, clients, settings | Bluetick's workspace, run by the founder |
| `/school` — the school head's view | The same thread |
| `/login`, `/signup`, Supabase Auth, `proxy.ts` role gates | Nothing. A phone number is the identity |
| `supabase/` — 74 migrations, RLS, RPCs, the `notify` edge function | Bluetick's own schema. Sharwin's project stays up, read-only, as the historical record |
| `lib/whatsapp/*` — the LLM agent on Twilio | Bluetick's assistant on its own number, `12402623933` |
| Razorpay checkout + webhooks | A payment link sent in the thread |
| Venues, coaches, plans, products read live from Supabase | `content/academy.json`, regenerated by `scripts/export-content.mjs` |
| The public "next session" labels on `/locations` | `/schedule`, fed by bluetick's diary endpoint |
| `e2e/`, `tests/`, `docs/plans/`, `.githooks/` | Deleted |

The academy's rows — venues, classes, coaches, sessions, the people — are
carried into bluetick by `scripts/export-to-bluetick.mjs`; that script and its
runbook are documented in `scripts/README.md`.

## THE SWITCH

In this order. Steps 1–4 are reversible on their own; step 5 is the one that
changes what the public sees.

1. **Set the env on Vercel** (Production), on the Sharwin project:
   - `BLUETICK_URL` — where bluetick is deployed.
   - `BLUETICK_DIARY_KEY` — the academy's workspace key (three hyphenated
     words). Server-only.
   - `NEXT_PUBLIC_BLUETICK_KEY` — the same key, public, so `wa.me` links can
     prefill it.
   - `NEXT_PUBLIC_WHATSAPP_NUMBER=12402623933`.

   Redeploy so the public values are baked into the client bundle. Nothing is
   live yet: `/schedule` will 404 from bluetick until step 4.

2. **Stop the notify cron.** In Sharwin's Supabase SQL editor:

   ```sql
   select cron.unschedule('notify-worker');
   ```

   The `notify` edge function runs every minute and sends reminders,
   cancellations and payment chases from the old system. If it keeps running,
   parents get messages from an academy that has moved — and links into an app
   that now redirects. **This must happen before the announcement in step 6.**

3. **Re-point Twilio.** In the Twilio console, set the old WhatsApp number's
   inbound webhook to `https://<the new deployment>/api/whatsapp` (POST). That
   route is now an autoresponder: it validates `X-Twilio-Signature` with
   `TWILIO_AUTH_TOKEN` and replies with one sentence and a link to the new
   thread. Send one message to the old number and check you get it back.

4. **Turn the workspace on in bluetick.** Set the academy workspace's
   `attrs.public_diary = true` (the import sets this) and `live = true` — the
   founder's own switch, the thing that says the assistant may talk to real
   people. Load `/schedule` against the new env and confirm a real week renders.

5. **Ship it.** Merge `bluetick-tenant` into `main` and promote the deployment.
   `/login`, `/signup`, `/app`, `/coach`, `/admin` and `/school` start
   redirecting to `/schedule`.

6. **The founder announces it.** From his own phone, in the existing parent and
   coach WhatsApp groups: the new number, and a link that opens a thread with
   it. This is not an automated broadcast — a group that has heard from a human
   for years should not first hear about the move from a robot, and Meta does
   not allow it anyway.

## THE REVERSAL

The site and the messaging reverse independently. Do the messaging first: it is
what people actually feel.

1. **Put the old site back.** Vercel → the previous production deployment →
   *Instant Rollback*. If the merge has to come out of `main` as well, revert
   the merge commit and redeploy. The old `/app`, `/coach` and `/admin` return
   exactly as they were; nothing in Sharwin's database was changed by the
   cutover.

2. **Re-point the Twilio webhook** back at the old deployment's
   `/api/whatsapp`, which is the LLM assistant again. The old number starts
   answering properly instead of forwarding.

3. **Re-schedule the notify worker** in Sharwin's Supabase:

   ```sql
   select cron.schedule(
     'notify-worker', '* * * * *',
     $$select net.http_post(
         url := '<project>/functions/v1/notify',
         headers := '{"Authorization":"Bearer <service role>"}'::jsonb
       )$$
   );
   ```

   (The exact command is in the header of the `notify` function in the old
   tree — take it from the reverted checkout rather than from memory.)

4. **Take bluetick off the air** for this tenant: set the workspace `live =
   false`. The diary endpoint keeps serving, which is harmless; the assistant
   stops replying.

5. **Recover anything booked in the meantime.** Every booking, cancellation and
   new person that happened while bluetick was live exists only in bluetick.
   Export the Sharwin workspace's rows — events, bookings, members — and apply
   them to Sharwin's Supabase **by hand**. There is no reverse import, and
   there should not be one: the two schemas disagree about what a person is,
   and an automated round-trip would invent data.

   The window matters. A reversal on day one is a handful of rows; a reversal
   after a fortnight is a reconciliation project. Decide fast.

## After

Once the academy has run a full month on bluetick with no reversal, the
Supabase project can be paused (not deleted — the historical record of who
attended what is a safeguarding artefact). `scripts/export-content.mjs` is the
only thing that still reads it; freeze `content/academy.json` before pausing.
